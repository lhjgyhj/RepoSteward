## 安装
Windows(Git Bash),在项目根目录执行:
```bash
cd backend && python -m venv .venv && ./.venv/Scripts/python.exe -m pip install --isolated -r requirements-dev.txt
cd ../frontend && npm install
```
macOS / Linux:把 `./.venv/Scripts/python.exe` 换成 `./.venv/bin/python`,其余相同。

## 启动与测试
- 启动后端(在 backend/): `./.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000`,访问 http://localhost:8000/health
- 启动前端(在 frontend/): `npm run dev`,访问 http://localhost:5173
- 测试(在 backend/): `./.venv/Scripts/python.exe -m pytest -q`
- 代码检查(在 backend/): `./.venv/Scripts/ruff.exe check .`
- 前端打包(在 frontend/): `npm run build`

## 配置
- 环境变量(只写名称和用途,值放 backend/.env,参考 backend/.env.example):
  - DATABASE_URL:异步数据库连接串
  - GITHUB_WEBHOOK_SECRET:Webhook 验签密钥
  - GITHUB_APP_ID、GITHUB_PRIVATE_KEY_PATH:GitHub App 身份
  - GITHUB_CLIENT_ID、GITHUB_CLIENT_SECRET:控制台 GitHub 登录
  - SESSION_SECRET:会话签名密钥
  - FRONTEND_URL:前端地址,用于登录回调和跨域

## 已知问题与解决办法
| 问题 | 原因 | 解决办法 |
|------|------|----------|
| pip 安装报 SSL 证书错误 | pip 全局配置指向抓包工具 Reqable 的证书 | 安装时加 `--isolated`,忽略全局配置 |
| pytest 提示 StarletteDeprecationWarning | 新版 Starlette 建议测试客户端换成 httpx2 | 暂不影响测试,先忽略 |
| ruff 报未使用的 import | 骨架阶段提前写入了 T1 要用的 import | 写完 T1 后应消失;没消失就删掉没用到的 import |
| 命令行里直接输 psql 找不到 | PostgreSQL 的 bin 目录不在 PATH | 用完整路径调用,或把 PostgreSQL 的 bin 目录加入 PATH |
