## 安装
Windows(Git Bash),在项目根目录执行:
```bash
cd backend && python -m venv .venv && ./.venv/Scripts/python.exe -m pip install --isolated -r requirements-dev.txt
cd ../frontend && npm install
```
macOS / Linux:把 `./.venv/Scripts/python.exe` 换成 `./.venv/bin/python`,其余相同。

## 启动与测试
- 启动后端(在 backend/): `./.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000`,访问 http://localhost:8000/health
- 启动前端(在 frontend/): `npm run dev`,访问 http://localhost:5173
- 测试(在 backend/): `./.venv/Scripts/python.exe -m pytest -q`
- 代码检查(在 backend/): `./.venv/Scripts/ruff.exe check .`
- 前端打包(在 frontend/): `npm run build`

## 决策层与模型(M2)

- **升级链**(与报告 §6.1 一致,不可用模型替换规则):规则 → 答「不确定」再交给模型(`deepseek_json` / `jev`) → 仍不确定 → 人。超额降级回纯规则(M3),所以 `rules` 后端必须始终能独立工作。
- **当前进度**:M2-T2 只实现 `decide(state, questions)` 的 `rules` 后端,先打通 D2;不调网络、不写库。模型再审接在规则返回「不确定」之后,不在 T2 里做。
- **不配默认模型**(用户 2026-11-17 确认):开发者 / 托管方不在 `.env` 或代码里预置基座 URL、模型名或 API Key。终端用户必须在控制台填自己的 URL 与密钥后才能使用模型再审;未配置时 `decide` 只走 `rules`,不发起模型请求。
- **统一基座**(同一决定):代码里只保留一个模型客户端,入参来自用户保存的配置。换供应商/模型由用户改控制台配置,禁止在 decide / 分拣 / 摘要里各自 `httpx` 一份。
- **测连通与生产同一套配置**:控制台可先「测试连接」,通过后再用于规则答「不确定」时的模型再审。API Key 禁止进 git、禁止打进日志、禁止写入 Decision/Suggestion。

## 数据契约（节点形状）

带教约定：讲到「payload / state / 会话」时，必须能在本节找到该节点的字段示例。数字均为示例。两套 id 不要混：GitHub 的 `installation.id` / `repository.id` 进带 `github_` 的列；我们表的 `id` 才给外键。

### 节点 0 — GitHub → `POST /webhooks/github`

**请求头**

| 头 | 示例 | 落到哪 |
|----|------|--------|
| `X-Hub-Signature-256` | `sha256=` + 对 **Body 原始字节** 的 HMAC-SHA256 | 只用于验签，不入库 |
| `X-GitHub-Delivery` | `"abc-1"` | `events.delivery_id`（唯一） |
| `X-GitHub-Event` | `"installation"` / `"issues"` | `events.type` |

**形状 A：安装 App**（`X-GitHub-Event: installation`）。没有单数 `repository`，不写 Event。

```json
{
  "action": "created",
  "installation": {
    "id": 12345678,
    "account": { "login": "octocat" }
  },
  "repositories": [
    { "id": 987654, "name": "hello-world", "full_name": "octocat/hello-world" }
  ]
}
```

| 取值 | 写入 |
|------|------|
| `installation.id` | `installations.github_installation_id` |
| `installation.account.login` | `installations.account` |
| （payload 常无 plan） | `installations.plan`，本阶段写死 `"free"` |
| `repositories[].id` | `repositories.github_repo_id` |
| `repositories[].name` | `repositories.name` |
| 刚落库的 `installations.id` | `repositories.installation_id` |

**形状 B：新开 issue**（`X-GitHub-Event: issues`）。没有 `repositories` 数组。

```json
{
  "action": "opened",
  "issue": {
    "title": "App crashes on launch",
    "body": "Traceback (most recent call last): ..."
  },
  "repository": { "id": 987654, "name": "hello-world" }
}
```

| 取值 | 写入 / 用途 |
|------|-------------|
| `repository.id` | 查 `repositories.github_repo_id`，命中后用该行主键当 `events.repo_id` |
| 请求头 Delivery / Event | `events.delivery_id` / `events.type` |
| 整个 `payload_dict` | `events.payload`（JSONB 原文） |
| `issue.title` / `issue.body` | **仅** 交给 `decide` 的 state，不是 Event 的单独列 |

查不到仓库行 → 不插 Event。重复 `delivery_id` → rollback，仍 202，不写第二套 Decision。

### 节点 1 — 表行（落库后）

`installations`：`{id: 1, github_installation_id: 12345678, account: "octocat", plan: "free"}`  
`repositories`：`{id: 3, installation_id: 1, github_repo_id: 987654, name: "hello-world"}`  
`events`：`{id: 10, repo_id: 3, delivery_id: "abc-1", type: "issues", payload: <形状 B 整份>, received_at: <带时区时间>}`

`event.id` 在 `session.add` 之后往往仍是 `None`，要 `flush` 才有主键，Decision 才能挂上。

### 节点 2 — `decide`（`backend/app/services/decide.py`）

**入**

```python
state = {"title": "App crashes on launch", "body": "Traceback: ..."}
questions = ["D2"]
backend = "rules"   # 本阶段只用这个；其它值问 D2 一律「不确定」
```

缺 `title`/`body` 当 `""`，不 500。

**出**（只含被问到的键）

```python
{"D2": "bug"}
# 合法值仅：bug / 功能请求 / 使用提问 / 文档 / 垃圾 / 不确定
# questions 不含 "D2" → 返回的 dict 不得有键 "D2"
```

T3：仅 `type=="issues"` 且 `action=="opened"` 时调用。答案是「不确定」也照样写 Decision 和 Suggestion。模型再审尚未编码。

### 节点 3 — Decision / Suggestion（T3 写入，挂 Event 不挂 Ticket）

`decisions`：`{event_id: 10, point: "D2", backend: "rules", answer: "bug", confidence: null}`  
`suggestions`：`{event_id: 10, action: "label", payload: {"type": "bug"}, mode: "suggest", status: "pending", decided_by: null}`

`payload.type` 与 Decision.answer 相同。不调 GitHub 打标签。Key 禁止写入这两张表。

### 节点 4 — 登录会话（cookie 名 `session`）

```json
{"github_user": {"login": "octocat", "github_id": 1, "repo_ids": [987654]}}
```

`repo_ids` 是 GitHub 仓库 id（`github_repo_id`），不是 `repositories.id`。未登录 `GET /api/events` → 401；`repo_ids` 为空 → `[]`。

### 节点 5 — `GET /api/events` 响应

```json
[
  {
    "id": 10,
    "type": "issues",
    "delivery_id": "abc-1",
    "received_at": "2026-11-17T12:00:00+00:00"
  }
]
```

`received_at` 必须是 `isoformat()` 字符串。本阶段列表不含 Decision/Suggestion。

### 节点 6 — 用户模型配置（未建表，形状先锁定）

控制台填写，**按使用者保存到服务器数据库**，不进 `.env`、不进 git、不进日志。产品无默认模型。未配齐 → 只走 rules。

```json
{
  "base_url": "https://api.example.com/v1",
  "model": "用户填写的模型名",
  "api_key": "用户填写的密钥"
}
```

Webhook 再审读库里这一行，不读浏览器 localStorage。测连通与生产同一套字段。

### 端到端（T3 正在接的路径）

```
形状 B POST
  → 验签 / 解析
  → Event(repo_id=3, delivery_id, type=issues, payload=整份 JSON)
  → flush 得到 event.id=10
  → state{title,body} = issue.title / issue.body
  → decide → {D2: bug}
  → Decision + Suggestion(pending)
  → commit，HTTP 202
  → 登录后 GET /api/events → 节点 5 那条
```

## 已知问题与解决办法
| 问题 | 原因 | 解决办法 |
|------|------|----------|
| pip 安装报 SSL 证书错误 | pip 全局配置指向抓包工具 Reqable 的证书 | 安装时加 `--isolated`,忽略全局配置 |
| pytest 提示 StarletteDeprecationWarning | 新版 Starlette 建议测试客户端换成 httpx2 | 暂不影响测试,先忽略 |
| ruff 报未使用的 import | 骨架阶段提前写入了 T1 要用的 import | 写完 T1 后应消失;没消失就删掉没用到的 import |
| 命令行里直接输 psql 找不到 | PostgreSQL 的 bin 目录不在 PATH | 用完整路径调用,或把 PostgreSQL 的 bin 目录加入 PATH |
