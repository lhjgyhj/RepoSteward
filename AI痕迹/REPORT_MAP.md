# 项目地图

## 报告概要
- 来源文档: doc/RepoSteward 仓库管家 PRD.md(v1.0)
- 项目目标: 面向中小开源维护者的 GitHub App。接收 issue / PR / 评论 / CI 事件,自动分拣、查重、追问缺失信息,把同一件事归成一个事务(Ticket),每天只把需要维护者拍板的事交给人。默认只建议不执行,关闭 issue、合并 PR 永远由人做。
- 技术栈: Python FastAPI + SQLAlchemy 2.x(异步)+ PostgreSQL(pgvector)+ Redis + Vue 3;模型侧为 Jev 决策层 + DeepSeek 生成层;运营后台用 SQLAdmin。
- 核心架构: 确定性内核(入库、去重、权限、状态写入、对外动作)+ Jev 决策层(固定选项判断)+ 生成层(写文字)。原则:模型只提议,程序裁决。

## 模块依赖
```
数据模型
  └─ 事件接入 ─┬─ 安装与账号 ── 控制台(Vue)
               └─ 决策层 ── 分拣与查重 ── 动作执行(权限表 + Outbox + 审计)
                                              ├─ 对人交互(建议队列、每日摘要)
                                              ├─ 额度与运营
                                              └─ 事务跟进(Router-Worker)── 灰度 ── v0.3
```
先有数据模型和事件入库,后面每一层都只读写数据库,所以必须先把 M1 打稳。

## 里程碑(对应报告 §9 的周计划)
| 里程碑 | 内容 | 报告周次 | 完成标准 |
|--------|------|----------|----------|
| M1 最小可运行流程 | 事件入库 + 控制台看到事件 | 第 1 周 | 测试仓库发一条 issue,3 秒内在控制台看到原始事件 |
| M2 分拣与建议 | 历史导入、向量建库、decide 接口、建议队列、人工确认后打标签 | 第 2 周 | 新 issue 3 分钟内出类型和相似 issue 建议,确认后才打标签 |
| M3 MVP 收尾上线 | 每日摘要、审计日志、额度降级、部署 | 第 3 周 | 每天收到摘要;超额自动降级为规则模式 |
| M4 决策后端评测 | 标注 200 条 issue,对比规则 / Jev / DeepSeek | 第 4 周 | 产出准确率、延迟、成本对比表 |
| M5 事务跟进 | Ticket、Worker、订阅直通、信息补全追问 | 第 5~6 周 | 后续评论直接进入原事务,不新建 |
| M6 CI 关联与灰度 | CI 关联、主动发现、灰度机制 | 第 7 周 | 主分支 CI 连续失败自动生成待确认事务 |
| M7 加分项 | 复现实验 或 Watchdog 二选一 | 第 8 周起 | 在自己的仓库真实跑通一次 |

M2 起的任务卡等进入对应里程碑时再拆,不提前展开。

## 里程碑与任务卡
### M1:最小可运行流程(进行中)
- T1:数据模型 —— Installation、Repository、Event 三张表及迁移(§8)
- T2:Webhook 验签 —— 校验 X-Hub-Signature-256(§4.2 第 1 步、F2.2)
- T3:Webhook 端点 —— 入库、按 X-GitHub-Delivery 去重、快速过滤、返回 202(§4.2 第 2~3 步、F2.1~F2.3)
- T4:安装事件 —— 处理 installation 事件,记录安装和仓库(F1.1)
- T5:事件列表 —— 后端只读接口 + Vue 页面展示原始事件(第 1 周验收)
- T6:控制台登录 —— GitHub OAuth,只显示自己有维护权限的仓库(F1.2)
- 无 AI 关卡:里程碑末尾单独布置,AI 不介入
